# 权限常见问题

> 面向普通用户与管理员。架构细节见 [架构设计](./architecture.md)。

## 用 Google / 社交账号登录后，如何获得权限？

### 登录路径（产品侧没有「Google 按钮」）

DataView **不提供**一等公民的 Google / GitHub 登录按钮。社交登录配置在 **IdP（Logto / Auth Gateway 上游）** 的 Connector 中完成。

用户看到的产品入口仍是「使用统一账号登录」：

```text
DataView「统一登录」
  → LuminaryWorks Identity（Logto）
      →（可选）Google / GitHub / 企业 Connector
  → 回调 DataView → DataTalk 换票（SSO）
```

因此：是否出现「用 Google 登录」，由贵司 / 生态 Identity 管理员在 Logto 控制台启用 Connector 决定，而不是改 DataLuminary 前端。

### 登录后自动获得什么？

首次（或再次）SSO 成功后，DataTalk 会：

1. 将 IdP `sub` 映射为本地用户（无则自动创建）；
2. 确保该用户加入**默认组织**的有效会员关系（`membership`，来源一般为 `sso`）；
3. 在组织列表中呈现角色为 **`org_member`**（若尚未被管理员赋更高组织角色）。

这表示：你已经是平台默认租户的普通成员，可以进入组织上下文；**不等于**自动成为某空间的编辑者，也不等于拥有平台超管能力。

### 如何申请更高权限？

| 诉求 | 做法 |
|------|------|
| 进入某个业务空间 | 在空间列表 **「发现空间」** 点击 **申请访问**；由空间管理员在该空间 **空间设置 → 访问申请** 中通过。完整步骤见 [申请与审批](./usage.md) |
| 被管理员直接拉进空间 | 提供已注册邮箱；管理员在 **空间设置 → 空间成员** 中邮件邀请 |
| 成为组织管理员 / 所有者 | 请现有 `org_admin` / `org_owner` 在齿轮 → **组织 → 成员** 调整角色；或通过组织邀请链路接受邀请 |
| 平台级运维（开通组织、管全站用户） | 由 Identity 侧授予 `super_admin` / `platform_admin` 等角色，经外部角色映射落地；见开发者文档 [私有化对接](../develop/iam-private-deploy.md) |
| 商业功能被锁（升级提示） | 与计费 / 组织管理员确认 Subscription 或私有化 License，而非改 RBAC |

产品内可在设置页查看自身组织与角色；资源按钮上的锁与提示会区分「无权限」与「未购买 / 配额用尽」。

## 申请了空间访问，审批入口在哪？

**不在**右上角齿轮的「组织 → 成员」。

请空间创建者 / 管理员：

1. 登录后进入该空间（「我的空间」）；
2. 顶栏打开 **「空间设置」**（勿点齿轮）；
3. 左侧 **「访问申请」** → 通过 / 拒绝。

详见 **[申请与审批](./usage.md)** 中「场景 B：审批别人的访问申请」。

## 分享三种可见范围

产品新建分享时，可见范围收敛为三种（旧值仅存量兼容，UI 不再提供）：

| 模式 | 值 | 谁能看 | 典型用途 |
|------|-----|--------|----------|
| **邀请码** | `invite_code` | 知道邀请码的人 | 定向外发、临时协作 |
| **第三方嵌入** | `third_party_embed` | 登记过的外部应用经 Embed Token | 门户 / 业务系统 iframe |
| **完全公开** | `public` | 任意持有链接的人（匿名） | 对外公示、市场页 |

### 共同门闸

无论哪种可见范围，仍受既有 **审核**（`approved`）与 **发布生命周期**（`publish`）约束。未审核通过或未发布的分享不能被打开。

### 行为差异

- **邀请码**：公开查看页需提交正确邀请码后建立 session。
- **第三方嵌入**：不走邀请码公开页；由宿主后端 `POST /api/embed/token/exchange`，浏览器再 `POST /api/embed/session`。见 [嵌入对接](../develop/embed-integration.md)。
- **完全公开**：审核通过且发布后，匿名可直接建立分享 session，**无需**邀请码；不引入密码或额外过期字段（过期由分享启停 / 审核状态控制）。

### 存量兼容

历史上可能存在 `authenticated_space_members`、`specific_users`。后端仍可读旧数据以免破坏存量链接；**新建** UI 只呈现上表三种。
