# 权限使用指南：申请与审批

> 面向普通用户与空间 / 组织管理员。说明「我的空间」能看什么、如何申请加入别人的空间、审批入口在哪。  
> 概念总览见 [概念](./index.md)；架构见 [架构设计](./architecture.md)。

本文解决最常见的困惑：**申请了访问，却找不到审批页面**——审批不在右上角齿轮的「全局设置」里，而在**被申请的那个空间**内。

---

## 1. 先分清两套「设置」

| 入口 | 路由示例 | 管什么 |
|------|----------|--------|
| 右上角 **齿轮** | `/#/settings/...` | **组织 / 平台**：成员、角色、账单、许可证、平台用户等 |
| 进入空间后顶栏 **「空间设置」** | `/#/{空间UID}/settings/...` | **当前空间**：成员与访问申请、分享与嵌入、数据权限 |

**审批空间访问申请 → 只用「空间设置」**，不要点齿轮。

顶栏文案已改为「空间设置」，避免与齿轮「设置」混淆。

---

## 2. 「我的空间」和「发现空间」

登录后打开空间列表（`/#/space`）：

| 页签 | 含义 |
|------|------|
| **我的空间** | 你当前**能进入**的空间：自己创建的、已被邀请 / 申请通过加入的；组织管理员可见本组织下空间；平台管理员可见全部 |
| **发现空间** | 同组织内你**尚未加入**的空间，可在此发起 **申请访问** |

普通成员**不会**自动拥有别人创建的空间权限；看到别人的空间应走「发现空间 → 申请」，而不是期望登录后直接出现在「我的空间」。

---

## 3. 场景 A：申请加入别人的空间（申请人）

**典型角色**：用 Google / GitHub / 统一账号登录的普通用户（一般为默认组织的 `org_member`）。

### 步骤

1. 登录 DataView，进入 **空间列表**（`/#/space`）。
2. 切换到 **「发现空间」**。
3. 找到目标空间（例如超级管理员创建的 `test`）。
4. 点击 **「申请访问」**。
5. 状态变为 **「待审批」** 后等待；通过后该空间会出现在 **「我的空间」**，即可进入。

### 注意

- 申请对象是**空间**，不是组织成员席位。
- 若「发现空间」里没有目标空间：可能不在同一组织，或你已是成员（请回「我的空间」查看）。
- 申请人**看不到**审批按钮；审批必须由该空间的管理员操作（见下一节）。

---

## 4. 场景 B：审批别人的访问申请（空间管理员）

**谁可以审批**：该空间的 `space_owner` / `space_admin`（以及具备该空间 `space:edit` 的角色）。  
**典型账号**：创建该空间的超级管理员（superadmin）。

### 步骤（务必按此路径）

1. 使用 **空间管理员账号**（例如 superadmin）登录。
2. 打开 **「我的空间」**，进入目标空间（例如 `test`）。
3. 看顶部导航：仪表盘 / 数据管理 / 报告 / 分享 / **空间设置**。
4. 点击 **「空间设置」**。
5. 左侧菜单进入 **「访问申请」**（在「空间成员」分组下，与「空间成员」列表并列）。
6. 在申请列表中点击 **通过** 或 **拒绝**。

### 直接地址

```text
/#/{spaceUid}/settings/members/access-requests
```

成员列表地址：

```text
/#/{spaceUid}/settings/members
```

将 `{spaceUid}` 换成该空间的 UID（进入空间后可从地址栏复制）。

### 审批通过后

- 申请人成为该空间成员（默认角色一般为 `space_viewer`，只读）。
- 申请人刷新「我的空间」后应能看到并进入该空间。
- 管理员可在 **「空间成员」** 页调整角色（如改为 `space_editor`）或移除成员。

---

## 5. 场景 C：管理员主动邀请（不必等申请）

空间管理员仍可**主动加人**，不必等对方在「发现空间」申请：

1. 进入该空间 → **空间设置 → 空间成员**。
2. 点击 **「邮件邀请」**（或同等文案的邀请按钮）。
3. 填写对方已在系统中注册的邮箱，选择空间角色后提交。

适合：已知协作方邮箱、需要直接授予编辑权限等情况。

---

## 6. 场景 D：组织成员 vs 空间成员（别混）

| | 组织成员 `/#/settings/org/members` | 空间成员 `/#/{spaceUid}/settings/members` |
|--|--------------------------------------|---------------------------------------------|
| 管什么 | 谁属于这家「公司 / 租户」 | 谁能进**某一个**协作空间 |
| 谁操作 | `org_owner` / `org_admin` | `space_owner` / `space_admin` |
| 与「申请访问」 | **不负责**审批空间申请 | 在 **访问申请** 页审批 |
| 组织邀请 | `/#/settings/org/invitations` | — |

常见顺序：

1. 用户登录后已在默认组织（或接受组织邀请加入某企业组织）；
2. 再申请 / 被邀请加入具体空间；
3. 空间审批通过后，才在「我的空间」看到该空间。

齿轮里的 **「组织 → 成员」** 解决的是「谁在公司花名册」；**进不了某个业务空间**，要找空间管理员走场景 B 或 C。

---

## 7. 场景对照速查

| 我想… | 我该… | 对方该… |
|--------|--------|----------|
| 进入别人的空间 | 「发现空间」→ 申请访问 | 进该空间 → 空间设置 → 访问申请 → 通过 |
| 被直接拉进空间 | 提供已注册邮箱 | 空间设置 → 空间成员 → 邮件邀请 |
| 成为组织管理员 | 联系现有组织管理员 | 齿轮 → 组织 → 成员 → 改角色 |
| 开通新企业组织 | 联系平台管理员 | 齿轮 → 平台 → 组织 |
| 配置嵌入应用 | — | 进入空间 → 空间设置 → **第三方应用**（分享嵌入分组） |
| 上传私有化许可证 | — | 齿轮 → 组织 → 许可证（私有化场景） |
