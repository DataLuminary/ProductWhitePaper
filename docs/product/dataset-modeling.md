# 数据集、语义模型与分析存储

> **受众**：产品经理、业务用户、售前、交付  
> **开发说明**：[数据集零配置供给 · 设计与实现](../develop/dataset-provisioning.md)

创建数据集后就能配图、问数。平台会自动发布一套可用的指标/维度。分析加速默认走 **直接查询** 或 **你自备的分析库 + DataLuminary 同步**；DataLuminary 托管分析存储默认关闭。

## 用户要记住的三件事

1. **数据集是分析入口**。图表、仪表盘和 AI 问数都绑数据集，不直接绑数据库表。
2. **语义模型是口径**。指标、维度、时间粒度由平台按字段自动生成并发布；之后可在数据集详情里改、再发新版本。
3. **分析存储是加速，不是另一种数据源**。界面只出现「直接查询 / 连接现有分析数据库 / DataLuminary 托管」。托管未开通时选项禁用，Tooltip 为「请联系管理员开通」。

## 怎么创建

### 原始数据集（选一张表）

1. 数据管理 → 数据集 → 从数据源选表、勾选字段。
2. 进入 **数据能力** 步骤（默认已填好，一般不用改）：
   - 语义模型：**自动生成并发布**
   - 分析存储：**直接查询**
   - 同步：若选择连接自备分析库，可选 **全量 / 增量 / 持续变更**，由 DataLuminary 执行
3. 批量选多张表时，整批共用上述默认值，也可以对单个数据集覆盖。
4. 完成后即可「立即配图」或进入数据集详情。

**高级选项**：连接你已有的分析数据库（Doris 等），由 DataLuminary 负责同步。DataLuminary 托管需管理员开通后才能选择。

### 联表数据集

联表把 **已有的原始数据集** 按关联键拼成一个虚拟分析对象，供配图和问数使用。用户不写 SQL；平台按配置安全编译 JOIN，不在业务库落物理视图。

#### 怎么建

1. 数据管理 → 数据集 → **联表**。
2. 先选同一关系型 **数据源**，再选该源下至少两个 **原始数据集**，配置关联类型（内连接 / 左连接等）与等值字段。
3. 预览结果 → 调整字段 → 进入 **数据能力**（默认自动发布语义模型 + 直接查询）。
4. 若写入分析存储，联表目前只支持 **全量刷新**。

若相关物理表还没有对应的原始数据集，需要先走「原始数据集」向导建好，再来联表。

#### 为什么联表选的是数据集，不是数据源里的表

这与「数据集是分析入口」一致，不是向导漏了选表：

| 原因 | 说明 |
|------|------|
| 分析边界 | 图表、仪表盘、语义模型、权限与 AI 都绑数据集，不直接绑数据库表 |
| 复用治理 | 展示名、指标/维度、类型映射等已在原始数据集上配置过，联表直接继承，不必每联一次重做 |
| 安全编译 | 表名与列名来自已登记的原始数据集白名单；禁止在联表向导里填任意表名或手写 SQL |
| 权限与血缘 | 能看数据源 schema ≠ 能拿某张表做分析；联表沿数据集 UID 做可见性与影响追踪 |
| 结构约束 | 源必须是同空间、同数据源的 **原始** 数据集；不能联「联表再联联表」，也不能跨数据源 |

一句话：**原始数据集 = 一张物理表的分析对象；联表数据集 = 多个原始数据集的受控 JOIN。** 「从数据源选表」发生在建原始数据集时；联表发生在治理层之上。

#### 和 AI 创建的关系

AI 问数协助建联表时，可以先从数据源里的物理表起草，但确认创建时仍会在同一事务内 **复用或自动补建** 对应的原始数据集，最终落库的联表配置仍指向数据集，而不是裸表名。手工联表向导目前要求你事先已有这些原始数据集。

## 创建完成后你会看到什么

| 状态 | 含义 | 配图 |
|------|------|------|
| 语义模型已就绪 | 已按字段生成并发布 v1 | 可以立刻选指标/维度 |
| 直接查询 | 未接入分析存储，或托管未开通 | 图表查业务库，可用 |
| 分析存储准备中 | 正在把数据同步到自备或托管分析库 | 完成前仍查业务库 |
| 已切换分析存储 | 首次全量成功，后续查询走加速 | 对配图无感切换 |
| 失败可重试 | 同步失败或托管不可用 | 数据集和语义模型仍在；查询继续直连 |

切到分析存储之后，若同步过期，图表会明确提示数据可能陈旧，而不会悄悄返回过期结果。

## 语义模型怎么改

数据集详情 → **语义模型**：

- 默认提示「已自动配置，可直接配图」。
- 用表格编辑维度、指标、聚合、格式、时间粒度（日 / 周 / 月 / 季 / 年）；不必手写冒号分隔的公式文本。
- 没有合适数值列时，平台会生成稳定的 **行数** 指标，保证指标卡也能开箱使用。
- 改完后发布新版本。图表始终跟随 **最新已发布** 口径；若某张图绑定的指标/维度被删掉，需要重新绑定，不会偷偷改用旧字段名。

空间设置里的 **语义词** 只做同义词和检索别名，不能另造一套指标定义。

## 分析存储怎么选

数据集详情 → **分析存储**：

| 选项 | 适合谁 | 你要填什么 |
|------|--------|------------|
| 直接查询 | 默认路径；表不大，或不需要加速 | 无 |
| 连接现有分析数据库 | 自备 Doris 等分析库（SaaS / 私有化主路径） | 主机、库、表；同步由 DataLuminary 负责，或对接你已有同步体系 |
| DataLuminary 托管 | 管理员开通后的托管集群 | 无。未开通时选项禁用，提示「请联系管理员开通」 |

同步文案是「全量 / 增量 / 持续变更」。增量与持续变更只在原始数据集且源表具备主键 / 水位条件时出现；联表固定全量。

也可以切回直接查询：同步会暂停，已有图表继续使用同一数据集。

## 配图与 AI

- 查询类图表只选已发布语义模型里的指标和维度，**没有图表 SQL 模式**。
- 图片 / 视频 / 富文本等媒体面板不查数。
- AI 问数走同一套已发布口径；空间里还没有数据集时，Agent 可以协助创建数据集，但不能跳过数据集直接连库出图。

## 不会做的事

- 不会把 Doris、ClickHouse、SeaTunnel 当作用户必须选择的数据源或引擎商标。
- 不会在托管模式下向普通用户展示分析集群的主机、端口或密码。
- 不会在首次同步失败时假装「已经在用分析存储」；失败时仍可直连，语义模型仍然可用。
- 不会在手工联表向导里直接选数据源物理表并绕过原始数据集（须先有或由 AI 路径补建 original）。
- 不会支持跨数据源联表，也不会支持以联表数据集再作为联表源（禁止联表叠联表）。
- 不会让图表或浏览器提交任意 SQL 去物化联表。
- 不会在分析数据过期时静默返回旧结果。
- 不会在 DataLuminary 自营环境默认提供共享 Doris（内存与海量导入成本）；开通前只提示联系管理员。

## 权限与套餐

需要有数据集编辑权限才能创建和改存储。DataLuminary 托管另受部署开关与套餐能力 **分析存储** 约束；未开通时创建仍成功（直连 + 已发布语义模型）。
