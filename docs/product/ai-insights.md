# AI 洞察

> **受众**：产品经理、业务用户、售前、交付  
> **开发说明**：[AI 洞察 · 设计与实现](../develop/ai-insights.md)

DataLuminary 用 **一个** AI 对话框完成问数、洞察和生成图表 / 仪表盘。逻辑名 **DataInsight**。这是 **Pro** 能力；Free 用户仍能看见入口，点击后引导升级，传统拖拽 BI 路径不变。

## 已上线能力

| 能力 | 说明 | 产品入口 |
|------|------|----------|
| 自然语言问数 | 例如「近 30 天销售额趋势」——围绕空间内你有权限的数据集回答 | 右下角 DataInsight |
| 可解释洞察 | 趋势、环比、同比、TopN、贡献度、简易异常；**数字来自平台查询**，不是模型口算 | 对话里的证据卡 |
| 一句话生成 | 生成可继续编辑的图表与仪表盘，并跳进现有编辑器 | 对话 + 写操作确认卡 |
| 自配模型 | DeepSeek、豆包、OpenAI、Anthropic、Gemini 或 OpenAI 兼容接口；密钥只写不读 | **空间设置 → 模型配置** |
| 语义词 | 指标 / 维度 / 同义词 / 规则，帮助 Agent 选对口径 | **空间设置 → 语义词** |
| 知识库 | 上传 PDF / DOCX / Markdown / 文本，作制度与背景引用 | **空间设置 → 知识库** |
| 洞察日程 | UTC cron 定时跑提示词，结果写入专属会话 | **空间设置 → 洞察日程** |
| 企业 MCP | 给 Cursor / Claude 等外部 Agent 签发空间令牌，调用同一套工具 | **空间设置 → MCP 令牌** |

## DataInsight Agent 工作区

对话框是持久工作区：会话历史、新建 / 重命名 / 归档、从消息 fork、工具确认卡。
企业文档只作引用，事实数字仍来自查询。

当空间只有数据源而没有数据集时，Agent 可在用户具备权限的前提下检查表和字段，
生成数据集草案；确认创建后走与界面相同的零配置供给（自动发布语义模型，默认直接查询；可连接自备分析库并由 DataLuminary 同步），再进行洞察。它不会跳过数据集直接连接数据库生成图表。详见 [数据集与分析存储](./dataset-modeling.md)。

## 怎么用

1. 登录后进入某个空间。
2. 右下角蓝色 AI 按钮（DataInsight）。
3. 没有 Pro / `ai.analysis` 权益时：点击弹出升级提示。
4. 有权益时：打开对话面板；可直接问数，或说「生成一张折线图 / 销售仪表盘」。
5. 管理员在 **空间设置 → AI 洞察** 配置模型、语义词、知识库、洞察日程和 MCP 令牌。**没有已启用模型时不能对话**，点击 AI 会进入模型设置。

分享页、嵌入页、纯渲染页 **不会** 打开 AI。

## 知识库与 RAG（企业怎么用）

DataInsight 有两类检索，不要混成「把公司所有数据丢进一个向量库」：

| 类型 | 谁维护 | 用来做什么 | 不用来做什么 |
|------|--------|------------|--------------|
| **语义词** | 空间管理员在设置页维护口径 | 帮 Agent 选对数据集、字段、指标名 | 不当作实时数字 |
| **知识库** | 上传制度、口径说明、业务背景 | 回答「这个指标怎么定义」并给出引用 | 不替代报表查询 |

问「这个月销售额多少」时：先检索语义词找到正确字段，再用平台查询算出数字；文档里的历史数字最多当引用，并标明版本。

### 向量存在哪里？

早期原型曾把 embedding 放在 PostgreSQL **JSONB** 里，在应用层算相似度。这样 **不能建向量索引、距离语义不稳定**，不适合产品。

当前实现：向量写在 **同一套 DataTalk PostgreSQL** 的 **pgvector**（`vector` 列），和空间、权限、文档元数据在一起。

- **不是** 再买一套独立的 pgvector / Milvus 集群。
- 语料按 **空间** 隔离；检索前先过权限，再搜向量。
- 规模到千万级 chunk 或延迟不达标时，再评估独立向量库（见工程契约）。

### SaaS 接入的企业

1. 租户管理员在该空间配置模型（自带密钥，或后续的托管额度）。
2. 在 **语义词** 里维护本公司口径；在 **知识库** 上传可公开给本空间成员的制度文档。
3. 业务用户只使用 DataInsight 对话框，不必理解向量或数据库。
4. 文档与向量落在该部署的 DataTalk 库中，**不** 与其他租户混库检索。
5. 分享 / 嵌入链接默认 **不** 走文档 RAG，避免外链把制度全文带出去。

企业 **不需要** 自建向量集群才能用 RAG。需要的是：空间权限、`ai.analysis`（语义与问数）、文档检索另需 `ai.doc_rag` 权益。

### 私有化部署的企业

与 SaaS **同一套产品能力**，差别只在数据不出你的机房：

1. 安装时 PostgreSQL 必须带 **pgvector** 扩展（交付镜像使用 `pgvector/pgvector`，不是普通 `postgres` alpine）。
2. 跑库迁移（含把历史 JSONB embedding 转为 `vector`）。
3. 模型：默认 **空间 BYOK**（密钥进 Vault，只写不读）。可把流量指到内网兼容接口，而不必连公有云。
4. 知识库文件在你方对象存储 / 本地上传目录；向量在你方 PostgreSQL。
5. 不强制接入独立向量中间件。运维只需保证 DataTalk 进程常驻（日程 worker 跑在该进程内）。

私有化 **不要** 再给每家客户单独搭一套 Milvus「才算 RAG」。首期就是「业务库 + pgvector」。

## 企业 MCP 如何暴露

MCP **不是** 浏览器插件，也 **不是** DataView 提供的服务。它是 DataTalk 上的可选 HTTP 适配器，和产品内对话框走 **同一组工具、同一套权限**。

| 项 | 说明 |
|----|------|
| 谁打开 | 部署管理员设 `AI_MCP_ENABLED=true`（**默认关闭**） |
| 谁签发 | 空间管理员在 **空间设置 → MCP 令牌** 创建 `dlmcp_` service token |
| 明文 | 只显示一次，落库只存哈希；可按令牌限流、白名单工具 |
| 调用谁 | DataTalk：`GET /api/ai/mcp/tools`、`POST /api/ai/mcp/invoke` |
| 调用方 | Cursor、Claude Desktop、内部 Agent 等，用 `Authorization: Bearer dlmcp_…` |
| 权限 | 令牌绑定空间与签发人；每次工具仍走 Casbin / 权益 / 数据策略 |
| 禁止 | 原始 SQL、删资产、读数据源密码、读模型密钥；写工具要确认令牌 |

SaaS：企业把 Agent 指到 **该租户的 DataTalk API**（经网关），不要指到 DataView 前端源。  
私有化：内网 DataTalk 基址相同路径；令牌不要进代码仓库。

产品内 DataInsight **不** 绕一层 MCP；MCP 只给「人机对话框之外」的外部 Agent。

设置页会展示 tools / invoke 地址和一条可复制的 curl。创建令牌后把示例里的 `dlmcp_YOUR_TOKEN` 换成刚复制的密钥即可联调。

## 权限与商业

```text
登录（Logto）→ 会员权益 ai.analysis（问数）/ ai.doc_rag（文档）→ 空间 / 数据集 / 仪表盘权限（Casbin）
```

- **没付钱**：入口可见，点击升级。
- **没资源权限**：对话里提示申请访问，而不是一串技术错误。
- 图表永远绑定 **数据集**。Agent 可以从授权数据源协助创建数据集，但不能跳过数据集直接分析或生成图表。

## 不会做的事

- 不会让模型写原始 SQL 或 HTML。
- 不会自动删除仪表盘或图表。
- 不会在对话里回显完整模型密钥。
- 不会把 Free 版的传统 BI 改成「必须用 AI」。
- 不会把文档里的数字当成实时报表。
- 不会在分享页 / 嵌入页打开 AI 或检索知识库。

## 当前交付边界

- 向量与业务数据同库（pgvector），不是独立向量集群。
- MCP 限流在 DataTalk 进程内；多副本需在网关加限流。
- 洞察日程在 DataTalk 进程内执行，该进程需常驻；邮件订阅仍为后续能力。

## 与生态的关系

模型调用走 LuminaryWorks AI Platform 契约（本地 BYOK 适配器可先落地；设中央网关地址后可切换）。领域智能（语义层、分析引擎、ChartIntent、RAG ACL）留在 DataTalk，不交给中央网关判权限。

生态说明见 [启明工坊 · AI 平台](https://docs.luminaryworks.dev/develop/ai-platform)（上线后）及 MetaRepo 规格。
